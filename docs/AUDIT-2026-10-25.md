## 2. Backend / API issues

1. **ETag / If-Match (AGENTS.md rule 9):** no `ETag` or `If-Match` handling found anywhere in `backend/src` or `backend/modules`. Optimistic concurrency (412) is not implemented.
2. **Routes the UI calls that the backend does not map** (found by route cross-check; these come from the inherited `CrudApiService`, and pages mostly do not call them yet, so they are latent 404/405s):
   - CRM: `DELETE /leads/{id}`, `PUT|DELETE /opportunities/{id}`, `GET|PUT|DELETE /interactions/{id}`
   - Distribution: `PUT|DELETE /trips/{id}`
   - Manufacturing: `PUT|DELETE /workorders/{id}`
   - POS: `GET|POST|PUT|DELETE /sessions...` (backend has `/sessions/open`, `/close`, `/current`), `PUT|DELETE /orders/{id}` (backend has create and void only)
   - Purchasing: `PUT /receipts/{id}`
   - Services: `PUT|DELETE` on `/engagements`, `/retainers`, `/milestones`, `/time-entries`; `GET /milestones/{id}`, `GET /time-entries/{id}`
3. **Backend routes with no frontend caller (check each):** `GET /kpis` in Sales, Purchasing, Retail, Distribution, Manufacturing, POS (may be called through another wrapper; verify); `crm GET /analytics/kpis`, `services GET /analytics/kpis`; `crm GET /opportunities/pipeline-summary` and `GET /interactions/by-entity` (frontend builds a slightly different URL string, verify it matches); `manufacturing GET /costing/rollup/{id}` and `/costing/variance`; `projects GET /billing/overview`, `POST /billing/bill`.
4. **Inventory module** is thin (5 files, 430 lines) and still contains a stub entity (`InventoryModule.cs:18`, "proving that a module owns its own tables"). Cannot serve as the stock backbone for items 1.1 to 1.7 until extended.
5. **Single migration for nine modules** (`ModulesExpansion`). Verify against the model snapshot and the SQL Server rule (`erp-dev.db*` SQLite files exist in `backend/src/ERP.Api` but are git-ignored; rule says SQL Server only).
6. **Test coverage of new modules is thin:** references in tests per module: CRM 3, Distribution 2, Manufacturing 2, POS 34, Projects 2, Purchasing 2, Retail 3, Sales 4, Services 11. No tests for the missing integrations because they do not exist.
7. Lease/finance side (older modules) was not re-audited in depth; docs mark HR, Inventory and CRM (real estate) as "unverified depth".

## 3. Frontend / UI issues

1. **No i18n in the nine new module areas.** Zero uses of the translate pipe in `pages/sales|pos|crm|projects|purchasing|retail|services|distribution|manufacturing`, and no keys for them in `core/i18n/dictionaries.ts`. Hardcoded English `nzTitle`/`nzPlaceHolder` counts: Sales 27, Purchasing 19, Distribution 20, Manufacturing 16, Services 12, CRM 11, Projects 11, Retail 10, POS 8. Violates the EN/AR + RTL rule.
2. **Missing UI actions** (pages create/read but have no edit or delete): Services engagements, retainers, milestones, time entries; Distribution trips; Manufacturing work orders; POS sessions and orders; CRM leads, opportunities, interactions; Purchasing receipts edit. (Pages that do have them: Distribution routes update, Manufacturing BOM delete, POS register edit, Purchasing goods-receipt/PO/requisition delete.)
3. **Projects billing screen missing** (see 1.4).
4. **Typing:** heavy use of `any` / `as any` in new pages (`createPagedList<T>((q: any) => ...)`, `payload as any`, `res: any` in POS terminal/sessions/registers, `print.page.ts` POS mapping). API shape drift will not be caught by the compiler.
5. **Performance:** initial bundle over budget (1.68 MB / 1.50 MB); shell stylesheet over budget by 4.4 kB; `papaparse` is CommonJS.
6. **Unused imports** (TS-998113): `CurrencyPipe` in POS orders/sessions/terminal; `DatePipe`/`CurrencyPipe` in `portal-home`. Cosmetic but noisy.
7. **Error swallowing:** many `catchError(() => of([]))` calls (onboarding, legal-entities, custom-fields, invoice-detail, portal pages, shell menu) hide API failures from users (unverified impact).
8. **Large single-file components** (e.g. `shell.component.ts` over 1,300 lines, `print.page.ts` ~1,600 lines, `pos-terminal.page.ts` ~660+): hard to maintain and test.
9. Shared-UI rules (expand-search, hover-reveal buttons, shared pagination bar, skeleton loaders) were **not** checked on the nine new areas (unverified).
